> 适用周期：2026-07-21 至 2026-08-20  
> 适用版本：一个月邀测版候选  
> 使用者：项目负责人、测试/运维负责人、老板  
> 登记表最后更新：2026-09-06（支付回调边界与浏览器会话 P0 修复已提交自动化证据；R-02 仍等待非作者/真实沙箱复验；R-14 已提交实现和可重复证据，等待非作者低端设备复验）
> 决策原则：没有证据即视为未通过；P0 未关闭不得接收真实款项

## 1. 风险等级与处理时限

| 等级 | 定义 | 首次响应 | 升级规则 |
| --- | --- | --- | --- |
| P0 | 可能造成资金、数据、账号或合规重大损失，或阻断核心交易 | 2 小时内 | 立即停止扩展功能并通知项目负责人；关闭前不得上线 |
| P1 | 严重影响主要用户流程、发布稳定性或运营效率 | 1 个工作日内 | 2 个工作日未解决，升级给项目负责人 |
| P2 | 有替代方案，不阻断本月目标 | 2 个工作日内 | 纳入当周计划并明确解决日期 |
| P3 | 体验或维护性改进 | 周会评估 | 不挤占 P0/P1 资源 |

关闭风险时必须附代码、测试、运行记录、截图或决策纪要之一，不能只把状态改为“完成”。

### 1.1 实时更新协议

每名开发者在 Git 提交和 PR 中都必须给出风险判断与解决方案：

1. Commit 标题使用 `<type>(<scope>): <TASK-ID> [<R-ID>|R-none] <目的>`，例如 `fix(order): BE-102 [R-01] use server pricing`。
2. PR 必须填写问题、根因、解决方案、修改范围、验证证据、回滚方式和关联风险；不能只写“修复完成”。
3. 关联已有风险时，在同一 PR 更新本文件中的状态、当前方案、证据/PR 和最后更新时间。
4. 发现新风险时，当天新增 `R-xx`；不能等到周会或发布前补登记。
5. 判断风险无变化时，在 PR 明确填写 `R-none` 及理由；评审人可以否决不合理判断。
6. P0/P1 关闭必须由非作者验收；成员 4 每天检查登记完整性，阶段验收日复核全部开放风险。

允许的状态只有：`待确认`、`待处理`、`进行中`、`待验收`、`已关闭`、`已接受`、`外部阻塞`、`监控中`。`已接受` 仅适用于老板书面接受且有限期缓解方案的 P1/P2，P0 不得接受后上线。

### 2.3 R-14 性能与降级证据

- 失败边界：[`Product3DViewer.vue`](../../ecommerce/frontend/src/components/Product3DViewer.vue) 在 WebGL 不可用、GLTF 加载失败、八个必需装配节点缺失/为空或超过 `8,000 ms` 加载预算时发出结构化失败事件；[`DIY.vue`](../../ecommerce/frontend/src/views/DIY.vue) 收到事件后自动进入清单模式。
- 交易连续性：清单直接复用同一份 `selected`、`compatibilityChecks`、`totalPrice` 和价格来源状态；提供“整套加入购物车”和“加入并前往结算”。降级会停止渲染循环并卸载失败查看器；重试时 3D 在隐藏状态重新挂载，清单保持可操作，只有收到 `ready` 才返回 3D。
- 自动化：[`product-3d-viewer-resilience.test.js`](../../ecommerce/frontend/src/__tests__/product-3d-viewer-resilience.test.js) 分别覆盖四个真实触发点；[`diy-flow.test.js`](../../ecommerce/frontend/src/__tests__/diy-flow.test.js) 覆盖四类事件到清单模式的联动、查看器外壳超时，并验证选件、兼容、价格、购物车、结算和重试连续性。`npm run check` 于 2026-08-10 通过：12 个文件、73 项测试全部通过，类型检查和生产构建通过。
- 性能：生产构建将 DIY 页面与 3D 分为异步块；`DIY` 为 `43.35 kB`（gzip `15.25 kB`），`Product3DViewer` 为 `633.85 kB`（gzip `164.06 kB`）。3D 块仍超过 Vite 的 `500 kB` 告警线，因此本切片以异步隔离、失败后释放查看器和 8 秒自动降级控制阻断风险，后续仍需继续拆包/减重。
- 渲染抽测：本地前端在 `1280×720` 与 `390×844` 下验证清单模式、部件行切换、兼容/核价区和交易按钮可见，移动端页面无横向溢出。当前本地后端商品接口返回 HTTP 500，故真实目录数据下的完整浏览器选件链路仍列入非作者复验；自动化测试使用确定性商品快照验证交易连续性。

## 3. 候选版本质量门槛

### 3.1 交易正确性

- [ ] 商品、优惠、运费和 DIY 配置均由服务端重新计价，客户端金额只作展示。
- [ ] 金额使用统一精度规则，不使用二进制浮点参与结算。
- [ ] 创建订单、支付回调、退款和库存变更具备幂等策略。
- [ ] 订单、支付、库存状态变化有时间、操作者和原因记录。
- [ ] 重复提交、并发库存、支付超时、乱序回调和退款失败均有自动化测试。

### 3.2 安全与隐私

- [x] 生产环境不加载 demo seed，不存在已知密码管理员（全新环境自动验证；历史数据卷仍须按证据文档只读排查）。
- [x] 密钥、数据库密码和第三方凭证仅由安全配置注入，生产预检错误不输出敏感原文。
- [x] 弱密钥/弱数据库与 Redis 密码、开发模式或错误 CORS 配置在生产基础设施启动前被拒绝。
- [ ] 登录、支付、上传、管理后台等高风险接口有限流和审计。
- [ ] 依赖审计不存在无处理结论的高危漏洞。
- [ ] 隐私政策、服务协议、账号注销和个人信息处理路径经过业务确认。

### 3.3 测试与发布

- [ ] CI 对每个变更执行前端类型检查、单元测试、构建、后端测试和 migration 单头检查。
- [ ] 订单、支付和购物车相关后端覆盖率不低于 75%，后端总覆盖率不低于 65%。
- [ ] 核心交易自动化用例通过率 100%，候选版连续 3 个工作日无 P0 缺陷。
- [ ] 至少一条移动端和一条桌面端 E2E 主路径通过。
- [ ] 发布包可追溯到提交版本，部署步骤和回滚条件已经评审。

### 3.4 运维与恢复

- [ ] staging 使用 HTTPS，配置形态与生产一致但数据和凭证完全隔离。
- [ ] 生产进程不开启热重载，不以 root 用户运行。
- [ ] 关键日志包含请求 ID；5xx、支付失败和备份失败能触发告警。
- [ ] 数据库与商品资产已备份，并在隔离环境成功完成至少一次恢复。
- [ ] 已记录恢复点目标 RPO、恢复时间目标 RTO、值班人和回滚负责人。
- [ ] 发布后健康检查、观察窗口、失败回滚和对账步骤可执行。

### 3.5 商品、运营与合规

- [ ] 20–50 个首发 SKU 的价格、库存、图片/模型授权、售后规则和负责人完整。
- [ ] 支付、退款、发票、物流异常、客服投诉有明确流程和响应时限。
- [ ] 经营主体、网站备案、支付商户与公示信息的责任人和完成状态可查。
- [ ] 老板已确认业务模式、首发渠道、目标地区和不可接受风险。

### 3.6 DIY 配置器

- [ ] 兼容检查区分“兼容”“不兼容”“未验证”，未实现的规则不计为通过。
- [ ] 每条兼容规则具有稳定规则 ID、参与部件、判断证据、严重级别和用户可执行的修复动作。
- [ ] 客户端筛选与服务端下单复核使用同一版本规则；不兼容或关键未验证配置不能进入结算。
- [ ] CPU/主板插槽、内存类型、主板/机箱板型、显卡限长、散热限高和电源冗余均有正反向自动化样本。
- [x] 3D 模型失败、超时、缺少装配节点或设备不支持 WebGL 时，自动进入清单模式且不影响选件、价格、购物车和结算。
- [ ] 精确型号搜索正确商品稳定排第 1；筛选结果显示命中数量、已用条件和兼容状态。
- [ ] 价格历史明确显示渠道覆盖、币种、检查时间和缺失来源；无来源数据不标记为已核验或历史低价。
- [ ] 弹层打开后背景不可聚焦，完整键盘路径、焦点回归、减少动态效果和至少一种屏幕阅读器抽测通过。

## 4. Go / No-Go 决策

### Go：允许进入受控邀测

同时满足以下条件才可进入受控邀测：

1. 所有 P0 风险关闭且证据有效。
2. P1 风险均已关闭，或有老板签字接受的限时缓解方案。
3. 第 3 节所有必选项通过。
4. 邀测人数、金额上限、SKU 范围、客服时段和紧急止损方式已确定。
5. 项目负责人、测试/运维负责人共同签字，老板作最终决定。

### No-Go：停止接收真实交易

出现以下任一情况必须判定 No-Go：

- 存在未关闭 P0，或无法证明支付、价格、库存正确。
- 无法恢复备份，或关键告警不能送达负责人。
- 生产仍存在测试账号、默认密码、弱密钥或未隔离数据。
- 支付/经营所需外部材料未完成，或客服、退款责任无人承担。
- 候选版存在可稳定复现的资金、权限、数据丢失或隐私缺陷。

No-Go 不等于项目失败。决策记录必须写明阻断项、责任人、预计解除日期和下一次复审时间。

## 6. 范围变更规则

新增范围必须同时写明业务收益、工作量、风险、依赖和被替换的原任务。以下事项不能通过删减验收来换取进度：服务端定价、支付验签与幂等、生产账号隔离、备份恢复、核心告警和 P0 自动化测试。
