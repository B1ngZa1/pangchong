# 四人一个月项目任务计划

> 周期：2026-07-21 至 2026-08-20  
> 目标版本：邀请制测试候选版  
> 使用方式：将“成员 1–4”替换为真实姓名；成员每天更新个人任务卡，项目负责人在每周验收后更新本总计划

## 1. 排期假设

- 四名成员按全职投入估算；若有人投入低于 80%，项目负责人必须减少范围，不得靠加班掩盖。
- 本月只选择一个正式支付渠道作为主线。
- 首发商品控制在 20–50 个高质量 SKU。
- 外部主体、备案、支付和开票材料由老板指定业务负责人并行推进。
- 大型架构重构采用逐模块迁移，不在同一个 PR 中同时重写订单、支付和库存。

## 9. 日常协作节奏

- 每日 10 分钟同步：昨天产物、今天目标、阻塞项。
- 每天 17:30 前在个人任务卡或看板更新：实际完成内容、证据、次日目标、风险 ID 和 PR。
- 每个 PR 控制在可独立评审范围内，支付/权限/迁移/生产部署必须双人批准。
- 每个阶段倒数第二天预验收，最后一天按可运行产物正式验收；验收日为 07-27、08-03、08-10、08-17。
- 任务状态更新在本文件或项目看板中；文档与看板必须使用同一任务 ID。
- 每个 PR 必须说明关联风险和解决方案，并按[开发与 Git 指南](05-development-and-git-guide.md)同步更新风险登记表。
- 任何 P0 缺陷立即停止扩展功能，先修复并补回归测试。

## 10. 月末成功标准

本月成功不等于“已经公开商业化”。成功标准是：项目具备可信交易沙箱、可控 staging、首发商品集、自动质量门禁、可观测性、备份恢复和明确的公开上线门槛，老板可以基于证据决定下一阶段投入。
