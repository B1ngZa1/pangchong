## 计划基线

- 建议周期：2026-07-21 至 2026-08-20；实际启动日期变化时，所有日期整体平移。
- 团队规模：4 人，默认每人全职投入。
- 一个月目标：从“功能原型”推进到“邀请制测试/真实支付沙箱验收”，不把一个月包装成完整商业化上线。
- 参考基线：[商业化部署完成度评估](../audits/commercial-readiness-2026-07-17.md)。

## 使用方式

1. 老板先确认策划书中的 6 项决策。
2. 项目负责人把成员 1–4 替换为真实姓名，并确认角色是否匹配能力。
3. 每天 17:30 更新个人任务卡；07-27、08-03、08-10、08-17 按验收标准正式验收，不以“开发完成”代替“验收通过”。
4. 所有阻断项登记在风险表；超过 2 个工作日仍未解决时升级给项目负责人。
5. 2026-08-18 至 2026-08-20 只做验收、修复和汇报，不再扩大范围。
6. 每个 commit/PR 必须提供任务 ID、风险判断、解决方案、验证和回滚；风险登记与代码在同一 PR 更新。

## 状态约定

- `未开始`：尚未进入执行。
- `进行中`：已有负责人和预计完成日期。
- `待验收`：产物已提交，等待非作者验收。
- `已完成`：验收证据已记录。
- `阻塞`：外部输入或关键依赖缺失，负责人无法继续。
