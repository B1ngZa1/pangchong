## 负责解决的架构问题

| 架构问题 | 解决方案 | 完成标志 |
| --- | --- | --- |
| 页面直接拼接 API 与业务状态 | 先把 checkout/payment 拆为 feature，页面只编排流程 | 状态转换可单测，页面不自行推断支付成功 |
| JS/TS 与 DTO 漂移 | 维护 `api/index.d.ts` 或生成契约，关键响应做类型收敛 | CI 类型检查通过，契约变化有联合评审 |
| 错误状态分散 | 建立统一加载、空、失败、重试和客服模式 | 核心页面错误体验一致 |
| 客户端金额可能被误用 | 请求只发 ID、数量、版本，展示服务端返回的权威金额 | 改价不影响订单，价格变化能提示确认 |
| 3D 包过大 | 动态加载查看器/模型，记录 632 KB 基线并做对比 | 首屏不加载 3D 包，移动端指标改善 |
