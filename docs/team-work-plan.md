# 胖虫电商项目五人分工方案

## 1. 分工原则

- 采用“模块主责 + 全员商品配额”方式：每人对一个技术模块最终负责，同时共同完成 2000 个商品的数据、照片和粗模验收。
- 3D 展示以低面数 Web 模型为目标，不制作工程级 CAD。优先维护 30～80 套品类母版，通过尺寸、颜色和贴图生成 SKU 变体。
- 主责人负责制定规范、代码评审和验收，不代表相关工作只能由主责人完成。
- 下表中的“组员 1～5”在确定成员后替换为真实姓名。

## 2. 五人职责

| 成员 | 主责方向 | 核心任务 | 主要交付物 |
|---|---|---|---|
| 组员 1（组长） | 项目管理、架构与集成 | 拆分里程碑；维护需求和接口约定；处理跨模块问题；审核合并；负责订单、支付和关键业务闭环 | 项目计划、接口约定、集成版本、评审记录 |
| 组员 2 | 商城前端与交互 | 首页、商品列表、详情、购物车、结算、用户中心；响应式适配；图片加载与错误降级 | 用户端页面、组件测试、交互说明 |
| 组员 3 | 3D/CAD 资产流水线 | 制定粗模规范；维护 Blender/CAD 母版；GLB 导出、压缩和节点检查；维护 3D 查看器及降级方案 | 30～80 套母版、导出规范、模型检查工具、3D 展示模块 |
| 组员 4 | 后端、数据库与商品管理 | FastAPI 接口；PostgreSQL 模型和迁移；管理后台；CSV/Excel 批量导入；图片和模型元数据管理 | API、数据库迁移、批量导入工具、后台商品功能 |
| 组员 5 | 测试、部署与文档 | 自动化测试；Docker/Nginx；对象存储/CDN；备份、日志和监控；部署文档、演示材料和验收清单 | 测试报告、部署版本、运维手册、答辩材料 |

## 3. 2000 个商品的共同配额

商品主数据确定并冻结 SKU 编号后，按照编号分配：

| 成员 | 商品范围 | 每个商品的完成标准 |
|---|---:|---|
| 组员 1 | SKU 0001～0400 | 资料录入、照片核对、模型/模板绑定、页面验收 |
| 组员 2 | SKU 0401～0800 | 资料录入、照片核对、模型/模板绑定、页面验收 |
| 组员 3 | SKU 0801～1200 | 资料录入、照片核对、模型/模板绑定、页面验收 |
| 组员 4 | SKU 1201～1600 | 资料录入、照片核对、模型/模板绑定、页面验收 |
| 组员 5 | SKU 1601～2000 | 资料录入、照片核对、模型/模板绑定、页面验收 |

组员 3 负责模型规范和疑难资产，其他成员仍须完成自己 400 个商品的基础建模或模板变体。每批建议以 50 个 SKU 为一个验收单元，避免最后集中返工。

## 4. 推荐里程碑

| 阶段 | 目标 | 验收条件 |
|---|---|---|
| M0：规范冻结 | 确定商品字段、图片规格、粗模标准、Git 流程 | 录入模板和资产命名规则通过全员评审 |
| M1：链路打通 | 完成 20 个代表性 SKU | 商品导入、图片、GLB、详情页和后台修改全链路可用 |
| M2：批量生产 | 分批完成 2000 个商品 | 每批 50 个 SKU 通过自动检查和人工抽检 |
| M3：业务联调 | 完成购买、订单、支付和后台流程 | 核心自动化测试通过，无阻断级问题 |
| M4：部署验收 | 上线生产环境并完成演示 | 备份、监控、回滚、授权来源和验收文档齐全 |

## 5. Git 协作约定

### 分支

- `master`：只保存经过验收的稳定版本。
- `feature/<模块>-<说明>`：功能开发，例如 `feature/catalog-import`。
- `fix/<说明>`：缺陷修复，例如 `fix/model-load-fallback`。
- `data/sku-0001-0400`：商品数据批次。
- `asset/<品类>-<批次>`：资产清单、生成脚本和小型示例；大文件不直接进入 Git。

### 提交

- 提交前执行相关测试和 `git diff --check`。
- 使用 `feat:`、`fix:`、`data:`、`asset:`、`test:`、`docs:`、`chore:` 作为提交前缀。
- 一个提交只解决一类问题；禁止提交 `.env`、密钥、本地数据库、缓存和构建产物。
- 原始照片、CAD/Blender 源文件和批量 GLB 放对象存储，Git 仅保存生成脚本、资产清单、授权来源和校验值。

### 合并与评审

- 功能分支通过 Pull Request 合并，至少由另一名成员审核。
- 支付、权限、数据库迁移和生产部署改动需由两人确认。
- 合并前更新自己的分支并解决冲突；禁止对共享分支直接强制推送。

## 6. 单个商品完成定义

一个 SKU 同时满足以下条件才可标记完成：

1. 名称、品牌、型号、分类、价格、库存和规格字段完整。
2. 主图和图库能够加载，尺寸统一，并具有失败占位图。
3. 已绑定独立粗模或合适的品类模板，手机和桌面浏览器均可打开。
4. 模型许可、素材来源和版本信息可追溯。
5. 商品列表、详情页、购物车和订单快照中的信息一致。
6. 自动检查通过，并由非录入本人抽检。

## 7. 每周协作节奏

- 周初：确定本周模块目标和每人 SKU 批次。
- 每日：小批量提交，更新阻塞项，避免长期分支积压。
- 周中：完成一次接口和资产抽检。
- 周末：集成测试、演示本周成果并确定下一批次。
