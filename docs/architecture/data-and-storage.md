# 数据与存储

> 状态：当前边界与生产治理要求

## PostgreSQL

PostgreSQL 是用户、商品、购物车、订单、支付状态和服务协议的事实来源。生产 schema 应仅通过 Alembic 演进；`database/init.sql`、`components.sql` 和 `seed.sql` 用于本地初始化或受控数据导入，不能替代可审计迁移。

- 本地 Compose 可以挂载 demo seed。
- 生产 Compose 不得挂载 `database/seed.sql`，并应通过预检阻止弱凭据。
- 每次迁移必须验证“全新空库升级”和“已有数据升级”，同时保证只有一个 Alembic head。
- 订单金额使用数据库中的服务端快照；不要在历史订单查询时用当前商品价格回算。
- 高并发库存扣减需要锁、条件更新或库存流水，不能依赖前端防重复点击。

## Redis

Compose 已部署 Redis，但文档不把它写成已完成的业务缓存能力。引入任何缓存前必须说明：

- 缓存对象、TTL、失效条件和数据真值来源；
- key 命名与租户/用户隔离；
- 缓存不可用时的降级行为；
- 是否包含个人信息或凭据；
- 防缓存击穿、穿透和大 key 的策略。

Redis 端口只在私网开放，生产必须启用强密码；跨不可信网络时使用 TLS 或托管服务的安全连接。

## 商品图片与 3D 资产

当前支持两种后端：

| 后端 | 用途 | 生产要求 |
| --- | --- | --- |
| 本地 `uploads` | 本地开发、单机部署 | 持久卷、备份、容量告警，不能依赖容器可写层 |
| Supabase Storage | 托管对象存储 | Secret Key 仅后端持有，Bucket 权限、MIME、大小和路径都需限制 |

公开 Bucket 只适合确认可公开分发的商品资产。私有资产应使用私有 Bucket 和短时签名 URL。上传端生成不可预测的对象名，禁止路径穿越和覆盖未授权对象。

## 备份与恢复

上线前必须由业务负责人确认 RPO/RTO。最低要求：

1. PostgreSQL 自动备份并定期做异机恢复演练。
2. 对象存储开启版本或保留策略，并记录资产与商品的关联。
3. Redis 若仅为缓存可重建；若承载队列/会话，必须单独制定持久化与恢复方案。
4. 恢复演练记录包含备份时间、恢复耗时、校验查询和负责人签字。
