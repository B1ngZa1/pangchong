## 结论

DIY 移动端韧性 Playwright 套件在 `360×844`、`390×844`、`430×932` 三档视口的四个状态均已通过：**12 / 12**。套件仍保留零控制台错误、零页面异常、目录夹具、交互结果和像素比对断言；本轮没有放宽截图阈值。

## 401 / 资源请求调查与修复

路由进入 `/diy` 前会执行匿名会话恢复，向 `/api/auth/refresh` 发起 refresh-cookie 探测。视觉套件此前没有为该请求提供夹具，因此它会穿过 Vite 代理，在本地后端不可用时表现为资源 `401` 或 `500`，并偶发污染 `console.error` 断言。它不是 DIY 商品目录的成功响应，也不应由环境是否启动后端决定。

`e2e/diy-mobile.visual.spec.js` 现在：

- 为 refresh probe 返回显式的匿名会话响应（空 access token），保持未登录 UI；
- 为购物车、当前类目商品和价格历史保留确定性响应；
- 只拦截实际 origin 的 `/api/` 路径，避免误匹配 `/src/api/` 模块资源；
- 用 catch-all 记录并失败于任何未声明的 API 请求；
- 继续要求 `console.error` / `pageerror` 数组为空。

因此测试同时证明目录请求来自指定夹具，并能在未来新增未模拟资源请求时直接失败。

## 视觉确定性与基线裁决

基线与当前实现的差异来自已验证的设计系统迁移：`DsBuildSummary`、`DsStepIndicator`、工作台模式切换、WebGL 回退清单以及 `DsField` / `DsDiyPartPicker` 已替换旧的页面内结构。上述是有意的 UI 变更，故重新生成基线；未变的 `mobile-390/retry-back-to-3d` 不更新像素。

截图前测试现在等待：路由 entering transition 已移除、字体已就绪、连续两帧布局已提交；3D 状态另要求画布可见且具有非零面积。重试场景不再依赖固定的 600ms 延时。自动旋转仍会在正常滚动和重试场景中关闭，reduced-motion 场景仍由查看器断言为 `reduce`。

| 状态 | 断言 | 视口 | 结果 |
| --- | --- | --- | --- |
| 正常滚动 | 自动旋转关闭、页面可滚动且内容高于视口 | 360 / 390 / 430 | 3 / 3 通过 |
| WebGL 不可用 | 回退清单、原因、待验证、`¥0` 与禁用交易动作 | 360 / 390 / 430 | 3 / 3 通过 |
| 重试回 3D | 点击重试后恢复 3D、清单隐藏、自动旋转可关闭 | 360 / 390 / 430 | 3 / 3 通过 |
| 减少动态效果 | 查看器标记为 `reduce`，自动旋转停用提示可见 | 360 / 390 / 430 | 3 / 3 通过 |
