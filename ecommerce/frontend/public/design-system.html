02 / Principles

设计原则

用高对比黑色画布表现性能感，以虫翼绿承载关键行动；减少装饰，把配置、价格、状态和下一步操作放在最清楚的位置。

01 / CLEAR

先信息，后装饰

商品规格、价格来源、库存与订单状态必须先于氛围效果被看见。

02 / FOCUSED

绿色只指向行动

主按钮、链接、选中态和成功反馈使用品牌绿，避免整页泛绿导致层级失效。

03 / SYSTEMATIC

组合，不复制

页面优先复用 Token、基础组件与业务模式，不用一次性样式拼装新界面。

04 / ACCESSIBLE

状态不只靠颜色

错误、加载、禁用与成功状态同时使用文字、边框和语义标签表达。

03 / Foundations

Design Token

维护与 AI 巡检规范

设计系统不是一次性作业。每次功能迭代先检查复用，每月用 AI 做跨页面视觉巡检，再由负责人确认修复优先级。

变更流程

每次迭代
01

先查复用

在 Token、基础组件和业务模式中查找已有能力；确认缺口后才新增。

02

修改源头

颜色与尺寸修改 Token，交互修改共享组件，页面文件只负责业务组合。

03

覆盖状态

同时补齐默认、悬浮、聚焦、加载、错误、禁用、空状态和移动端。

04

验证再发布

执行 Token 校验、组件测试、构建与桌面/移动端视觉回归。

AI UI 体验巡检

每月一次
A

截图基线

按 1440px、1024px、390px 三个宽度抓取 19 个模板，并覆盖 Comfortable 与 Compact 两种模式。

B

视觉一致性

让 AI 检查颜色越界、密度模式误用、三栏比例漂移、字号断层与状态组件表现。

C

体验与文案

检查空状态、错误提示、加载反馈、操作命名和移动端主要任务路径。

D

形成维护单

按 P0 阻断、P1 易用性、P2 一致性、P3 美化分级，并记录修复截图。

前端文案提取

scripts/ui-copy.mjs

项目已提供文案提取、检查与回填流程。后期修改页面文本时，先提取为可审阅清单，再批量修改并执行 dry-run，减少散落在 Vue 文件中的遗漏。

npm run copy:extract
npm run copy:check
npm run copy:apply
